1. PREREQUISITES & SYSTEM REQUIREMENTS
================================================================================

Ensure you have the following software installed on your computer:

* Node.js:
  - Version: v18.x or v20.x LTS recommended (v18.0.0+)
  - Download: https://nodejs.org/
  - Verify installation in terminal:
      node -v
      npm -v

* Git:
  - Download: https://git-scm.com/
  - Verify installation in terminal:
      git --version

* Cloud Services & Accounts Needed:
  - MongoDB Atlas Account (Free M0 cluster): https://www.mongodb.com/cloud/atlas
  - Cloudinary Account (Free tier for image storage): https://cloudinary.com/

* Mobile Device Testing (Optional but recommended):
  - Install "Expo Go" app from Google Play Store (Android) or App Store (iOS).

2. REPOSITORY SETUP
================================================================================

Clone the repository to your local computer (if not already cloned):

    git clone https://github.com/boooooooot53-blip/Townify.git
    cd Townify

The project root structure:
    Townify/

    |-- Frontend/             (React Native + Expo Router)
    |-- README.txt
    |-- INSTALLATION_GUIDE.txt
    `-- .gitignore

3. BACKEND INSTALLATION & SETUP
================================================================================

Step 3.1: Navigate to Backend directory
--------------------------------------
Open your terminal and enter:
    cd Backend

Step 3.2: Install Dependencies
------------------------------
Run:
    npm install

Step 3.3: Configure Environment Variables (.env)
------------------------------------------------
1. In the `Backend` directory, copy `.env.example` to create `.env`:
   - On Windows PowerShell:
       Copy-Item .env.example .env
   - On Mac/Linux:
       cp .env.example .env

2. Open the newly created `Backend/.env` file in your editor and fill in the values:

    -------------------------------------------------------------------------
    PORT=5000
    NODE_ENV=development

    # MongoDB Atlas Connection String
    # Format: mongodb+srv://<username>:<password>@<cluster>.mongodb.net/<database_name>?retryWrites=true&w=majority
    MONGODB_URI=your_mongodb_atlas_connection_string_here

    # JWT Authentication Secrets (Generate random 32+ character strings)
    JWT_ACCESS_SECRET=your_jwt_access_secret_key_here
    JWT_REFRESH_SECRET=your_jwt_refresh_secret_key_here
    JWT_ACCESS_EXPIRES_IN=7d
    JWT_REFRESH_EXPIRES_IN=90d

    # Cloudinary Credentials (For storing user/worker images and IDs)
    CLOUDINARY_CLOUD_NAME=your_cloudinary_cloud_name
    CLOUDINARY_API_KEY=your_cloudinary_api_key
    CLOUDINARY_API_SECRET=your_cloudinary_api_secret

    # Email Service (Nodemailer - for OTP verification)
    EMAIL_USER=your_email@gmail.com
    EMAIL_PASS=your_gmail_app_password

    # Client URL (IP address of your frontend machine)
    CLIENT_URL=http://localhost:8081
    -------------------------------------------------------------------------

Step 3.4: Verify MongoDB Atlas Network Access
---------------------------------------------
1. Log in to your MongoDB Atlas dashboard (https://cloud.mongodb.com).
2. Go to "Network Access" in the left sidebar.
3. Make sure your current IP address is added, or add `0.0.0.0/0` (Allow Access from Anywhere) for development.
4. Go to "Database Access" and ensure your database user has read/write privileges.

Step 3.5: Test Backend Server
-----------------------------
Run:
    npm start

You should see output similar to:
    Connecting to MongoDB...
    MongoDB connected: <your-cluster-host>
    Townify API running on port 5000
    Environment: development
    Health check: http://localhost:5000/api/v1/health

Open your browser and navigate to:
    http://localhost:5000/api/v1/health
It should return a JSON status indicating the server is operational.

4. FRONTEND (MOBILE APP) INSTALLATION & SETUP
================================================================================

Step 4.1: Open a New Terminal Window
------------------------------------
Keep the backend running in your first terminal, and open a new terminal window.

Step 4.2: Navigate to Frontend directory
----------------------------------------
    cd Frontend

Step 4.3: Install Dependencies
------------------------------
Run:
    npm install

Step 4.4: Configure Environment Variables (.env)
------------------------------------------------
1. In the `Frontend` directory, copy `.env.example` to create `.env`:
   - On Windows PowerShell:
       Copy-Item .env.example .env
   - On Mac/Linux:
       cp .env.example .env

2. Find your computer's local Wi-Fi IP address:
   - On Windows: Run `ipconfig` in cmd/PowerShell and look for "IPv4 Address" (e.g., 192.168.18.16).
   - On Mac: System Settings > Network > Wi-Fi > Details (e.g., 192.168.1.100).
   - On Linux: Run `hostname -I`.

3. Open `Frontend/.env` and update it with your local IP address:

    -------------------------------------------------------------------------
    # Use your machine's local IP address so physical phones can reach the server
    EXPO_PUBLIC_API_URL=http://<YOUR_LOCAL_IP>:5000/api/v1
    EXPO_PUBLIC_SOCKET_URL=http://<YOUR_LOCAL_IP>:5000

    # Cloudinary configuration for client-side uploads
    EXPO_PUBLIC_CLOUDINARY_CLOUD_NAME=your_cloudinary_cloud_name
    EXPO_PUBLIC_CLOUDINARY_UPLOAD_PRESET=townify_data
    -------------------------------------------------------------------------

    NOTE: If running exclusively in a Web browser on the same PC, you can use:
    EXPO_PUBLIC_API_URL=http://localhost:5000/api/v1
    EXPO_PUBLIC_SOCKET_URL=http://localhost:5000

5. RUNNING THE COMPLETE APPLICATION
================================================================================

Terminal 1: Start Backend API
-----------------------------
    cd Backend
    npm start

Terminal 2: Start Expo Metro Bundler
------------------------------------
    cd Frontend
    npm start

Once Metro Bundler launches:
- Press `a` to open Android Emulator (if Android Studio emulator is running).
- Press `w` to open the app in your Web Browser.
- Press `r` to reload the application.

6. TESTING WITH PHYSICAL DEVICES (EXPO GO)
================================================================================

1. Ensure both your computer and your phone are connected to the SAME Wi-Fi network.
2. Open the "Expo Go" app on your Android or iOS device.
3. Scan the QR code displayed in Terminal 2 (Metro Bundler).
4. The JavaScript bundle will download to your phone, and the Townify app will start.

7. TROUBLESHOOTING COMMON ISSUES
================================================================================

Issue A: "Network Error" or "Unable to connect to server" on Mobile Phone
-----------------------------------------------------------------------
Cause: The mobile phone cannot reach the backend IP.
Fix:
1. Verify both the PC and the phone are on the exact same Wi-Fi connection.
2. In Windows Defender Firewall, allow Node.js through the firewall, or temporarily test on private network.
3. Check `Frontend/.env` and ensure `EXPO_PUBLIC_API_URL` uses your PC's actual IPv4 (e.g. `192.168.x.x`), NOT `localhost`.

Issue B: MongoDB Connection Failed / Timeout
-------------------------------------------
Cause: MongoDB Atlas IP whitelist restriction.
Fix:
1. Log in to MongoDB Atlas (https://cloud.mongodb.com).
2. Go to "Security" > "Network Access".
3. Click "Add IP Address" -> choose "Allow Access from Anywhere" (`0.0.0.0/0`).
4. Wait 1-2 minutes for the changes to apply, then restart the backend.

Issue C: Email/OTP not sending
------------------------------
Cause: Gmail requires an "App Password" rather than your standard account password.
Fix:
1. Go to Google Account > Security > 2-Step Verification.
2. Under "App Passwords", generate a 16-character password for "Mail".
3. Paste that 16-character string into `EMAIL_PASS` in `Backend/.env`.

Issue D: Port 5000 Already In Use
---------------------------------
Fix:
1. On Windows PowerShell:
     Get-Process -Id (Get-NetTCPConnection -LocalPort 5000).OwningProcess | Stop-Process -Force
2. Or change `PORT=5001` in `Backend/.env` and update `Frontend/.env` accordingly.
